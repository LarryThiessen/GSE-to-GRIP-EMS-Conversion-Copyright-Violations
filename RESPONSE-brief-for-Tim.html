GSE Companion — Response Brief

FOR: Timothy Luke (GSE)  ·  RE: the “gse-companion-disclosure” & Kephas video  ·  FROM: ScaryLarryGames  ·  CONFIDENTIAL DRAFT
Bottom line: The headline claim — “GSE Companion deletes your data” — is refuted by the discloser’s own evidence. The “paywall” and “bans” claims are misframed. One item is a legitimate fix (an unsigned diagnostic upload). The technical analysis is competent, so we win on facts, not denial.

1The delete never executed  DID NOT HAPPEN

The cleanup routine ran only under restricted && enforce. enforce is served by GET api.gse.tools/settings/access-policy. The discloser captured that endpoint himself and committed the results:

evidence/live_access_policy_*.json  →  "enforce": false   on 2026-06-20, 2026-06-21, 2026-07-09
  • The arming flag was off on every date he recorded — the routine never ran against anyone.
  • In the current build (0.4.22) the hardcoded cleanup is removed; enforce now only feeds the app’s status display.
  • Same bytes everyone has — installed app.asar SHA-256 27716e71c29d9403e0e225cec97f03995a864bf3f4855024e255ec21454cd6e1 matches his own hashes.txt entry for 0.4.22.

2“Paywall / EULA”  MISFRAMED

  • GSE addon is 100% free (CurseForge); no addon feature is sold.
  • GSE.Tools takes no money, runs no Patreon.
  • Creators optionally link their own Patreon for their own extras; class sets are public/free.

3“Surveils & bans”  MISFRAMED

4The one fair point — mostly shipped, one item open  STATUS

In 0.4.22 (the build the disclosure is about) an unsigned diagnostic gather/upload (SSE companion:request → zo() → /diagnostic/upload) read WoW-folder files, including addon error logs, and was not behind enforce. No evidence of misuse was found. Re-checked in 0.4.26 on 2026-07-29:

  • (a) Sign every request — NOT done. Still gated on an authenticated session plus a freshly-refreshed bearer token rather than a per-request ed25519 signature. ← this is the remaining item.
  • (b) Opt-in — partly. A requestFiles flag now raises a user-visible desktop notification; the kinds gather still runs on a server request.
  • (c) Scope it down — largely done. The gather now force-drops the errorlogs kind before collecting, so the BugGrabber/BugSack reader is unreachable from a server request; settings ships with accessToken and userSession deleted; the always-on portion is a GSE-only gather.
